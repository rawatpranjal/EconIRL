# GAIL Internal Notes

GAIL is retained as a contributed imitation-learning baseline. It matches
expert occupancy through an adversarial discriminator and updates a policy from
the discriminator-derived reward. Unlike AIRL, it is not designed to recover a
disentangled transferable reward. In this package it should be used for
behavior and occupancy comparison, not structural reward or counterfactual
claims.

## Algorithm

The tabular package implementation adapts GAIL to finite DDC-style MDPs:

1. initialize a discriminator `D(s, a)`;
2. sample expert state-action pairs from demonstrations;
3. sample model state-action pairs from the current policy;
4. update the discriminator to classify expert versus model occupancy;
5. derive a pseudo-reward such as `-log(1 - D(s, a))`;
6. update the policy with soft value iteration;
7. repeat until the policy stabilizes or `max_rounds` is reached.

The estimator supports tabular and linear discriminator modes. It uses soft
value iteration rather than PPO/SAC in the original continuous-control GAIL
setting.

## Interpretation

GAIL's output is useful for:

- testing whether adversarial occupancy matching improves over behavioral
  cloning;
- producing a policy imitation baseline;
- comparing occupancy divergence against other imitation methods.

It is not evidence for:

- identified primitive rewards;
- welfare comparisons;
- structural counterfactuals under changed transitions;
- transferable reward decomposition.

For reward-transfer claims, route to AIRL or AIRL-Het and check their validation
status.

## Current Validation State

The runner `../../../validation/estimators/gail/run.py` compares behavioral
cloning and GAIL on a 5x5 gridworld. It reports policy match and occupancy
Jensen-Shannon divergence and writes `validation/results/gail.json` when run.
There is no tracked GAIL release JSON in the current repository state.

This means GAIL is not part of the release artifact set. Before promoting it to
public RTD, add a tracked validation JSON with:

- expert and model occupancy divergence;
- policy match or policy TV against truth;
- convergence diagnostics;
- runtime;
- explicit statement that reward transfer is not certified.

## Debugging Order

1. Check discriminator type and reward transform.
2. Verify expert and model sampling use the same state-action encoding.
3. Inspect occupancy divergence before reward values.
4. Check policy-step mixing; adversarial loops can oscillate.
5. Compare against behavioral cloning.
6. Avoid reward-transfer interpretation unless an AIRL-style decomposition is
   added and validated.
